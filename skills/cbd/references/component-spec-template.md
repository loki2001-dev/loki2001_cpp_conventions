# 컴포넌트 명세 양식

설계 문서의 컴포넌트 절에 컴포넌트마다 아래 양식을 채운다. 비어 있는 칸은 "없음"으로 적는다.

## {ComponentName}

| 항목 | 내용 |
| --- | --- |
| 책임 | 이 컴포넌트가 하는 일 한 문장 |
| 대체 대상 | 옮겨 온 기존 프로세스나 기능. 새로 만든 경우 "신규" |
| 주기 | 타이머 주기. 이벤트 구동이면 "이벤트" |
| 외부 연동 | 상대 장치, 방향(우리가 대기 / 우리가 접속), 주소, 프로토콜 |

### 제공 인터페이스

| 종류 | 이름 | 설명 |
| --- | --- | --- |
| 발행 메시지 | `snake_case` 타입 | 언제 발행하는가 |
| 쓰는 상태 | `I{Kind}StatusWriter` | 어떤 필드를 쓰는가 |

### 요구 인터페이스

| 종류 | 이름 | 설명 |
| --- | --- | --- |
| 구독 메시지 | `snake_case` 타입 | 받으면 무엇을 하는가 |
| 읽는 상태 | `IStateReader` | 어떤 상태를 읽는가 |
| 전송 계층 | `TcpSocket`, `SerialPort` 등 | 블로킹이면 전용 스레드 |
| 설정 | `{name}_config` | 설정 키 목록과 허용 범위 |

### 동작 계약

| 항목 | 내용 |
| --- | --- |
| 스레드 | 루프 스레드. 전용 스레드가 있으면 이름과 이유 |
| 큐 | 이름, 상한, 넘침 정책(가장 오래된 것 버림 / 거절) |
| 실패 감지 | 무엇으로 끊김을 아는가 (연결 끊김, N초 무수신, 확인 응답 없음) |
| 복구 | 재접속 간격, 재등록, 세션 폐기 후 재대기 |
| 거절 이유 | 명령을 거절하는 조건과 화면에 보이는 이유 |
| 로그 | 장치 태그, 주요 분류 태그 |

### 시간 계약

값마다 출처(규격 절, 장치 명세, 측정)를 적는다. 해당 없는 행은 "없음"으로 적는다. 측정 최악값은 `Release` 빌드에서 잰다.

| 항목 | 계약 값 | 출처 | 측정 최악값 | 측정 조건 |
| --- | --- | --- | --- | --- |
| 주기 | | | | |
| 마감 | | | | |
| 핸들러 1회 실행 예산 | | | | |
| 지터 허용치 | | | | |
| 처리량(규격 / 과부하) | | | | |
| 큐 상한 / 고수위 | | | | |

### 시험

| 수준 | 항목 |
| --- | --- |
| 단위 | 코덱 경계, 상태 기계 전이, 범위 검사 |
| 가상 통합 | 가짜 장치가 실제로 받은 것으로 판정하는 시나리오 |
| 현장 확인 | 가상 시험으로 확인할 수 없는 항목 |
